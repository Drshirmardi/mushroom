# Assessment educational guidance v1 — FROZEN

Task F12-PJ-G02; Phase12, continuous owner authorization and physician publication boundary of ADR-0021/guidance-content-v1. Additive; old individual questionnaire/result/Mezaj/publication contracts unchanged. No new clinical algorithm or claims.

## Versioned map

One immutable AssessmentGuidanceVersion per exact questionnaire version/result-band/version number. Capture questionnaire hash, complete source band definition, technical algorithm WEIGHTED_SUM/v1 (existing identity), ordered1..10 approved same-clinic/same-locale guidance references with exact content hashes, ordered0..10 visible same-clinic Service snapshots(id/name/description), and explicit recommendConsultation boolean. Prices/booking/doctor availability/eligibility remain existing authoritative domains; a service recommendation never grants a booking or payment entitlement. No product/therapy recommendations inferred. Source matching/clinical appropriateness require physician review; technical identity is not scientific validity.

Existing PUBLISHED or RETIRED questionnaire only; validate its existing structure and exact unique source band, never synthesize classifications or change weights. DRAFT mapping creation is idempotent by actor+clinic+key; distinct commands allocate consecutive versions. Captured content/services must be available at creation and approval. Hash binds the complete mapping. Same DRAFT→APPROVED→REVOKED/final retention rules as guidance content; admin only authors/lists/gets/revokes unapproved drafts; qualified physician lists/gets/approves/revokes with exact hash and education-only/no diagnosis-or-individual-therapeutic-diet attestations. Reuse current database physician/profile/clinic/sign grant/active-session checks, no new grants.

For patient delivery, choose the highest version that ever obtained approval. A newer unapproved/withdrawn draft does not shadow a published version. Revoking the newest approved version blocks delivery without falling back to an older one. An explicitly later approved version can replace it. No automatic expiry or persistence of patient journey state.

Every referenced guidance must remain APPROVED with current qualified approving physician; every service must remain publicly visible under the existing patient-directory rules and retain exact approved name/description. Source semantic changes or revoked/unavailable references suppress the entire curated bundle until a clinician approves a replacement. Dynamic tariffs, availability and eligibility are deliberately not snapshotted as promises. No review grant is transferred to later text/mapping versions.

## API

- POST /v1/admin/assessment-guidance/versions, Idempotency-Key8..200 safe ASCII: assessmentVersionId, resultBandId1..100, guidanceContentIds1..10 unique UUID, serviceIds0..10 unique UUID, recommendConsultation:boolean. Source snapshots/algorithm/hash/reviewer fields server-owned.
- GET /v1/admin/assessment-guidance?page&pageSize&assessmentVersionId&status, GET /:id, POST /:id/revoke (unapproved only). ADMIN content manager plus explicit clinic and live database role.
- GET /v1/clinical/assessment-guidance (same filters), GET /:id, POST /:id/approve, POST /:id/revoke. Qualified same-clinic physician/current clinical-sign permission. Approve uses existing GuidanceApprovalDto against mapping contentHash; no generic ADMIN approval.
- GET /v1/assessment-submissions/:id/guidance. PATIENT + assessments:read:self + content:read:self, active own patient profile; exact COMPLETE/noninvalidated own same-clinic PUBLISHED/RETIRED questionnaire. Foreign/noncomplete/inconsistent ownership404. Responses exclude answers, score, private identities and payment details. No proxy partner/doctor read.

Patient response: submissionId, assessmentVersionId, status, mappingId/version/contentHash(nullable), content[], services[], recommendConsultation. Status READY only when all gates pass; otherwise empty recommendations and explicit PROVENANCE_UNRECORDED, PROVENANCE_UNSUPPORTED, CLINICAL_REVIEW_REQUIRED, NO_APPROVED_MAPPING, MAPPING_REVOKED or DEPENDENCIES_UNAVAILABLE. Source snapshot must have recorded exact supported algorithm, questionnaire hash, matching completion payload hash and matching actual band fields. Unknown/inconsistent provenance never guessed or rescored. Source band requiresReview=true blocks this automatic route until a separate professional patient-review contract exists. Questionnaire RETIRED may retain exact historical educational guidance; no switch to a new questionnaire.

All endpoints no-store, strict DTOs, bounded pagination(page1..10000,size1..50), explicit projections, safe stable errors. Admin/physician metadata audit and patient ClinicalAccessAuditService READ occur within the same transaction as returned data; audit failure denies the response and rolls back writes. Publication and version changes lock rows/namespace; database independently enforces retained immutable snapshots, same-clinic/source/reference/version/evidence shape and physician authority. No real mapping/content/clinical roles seeded.

Acceptance: real PostgreSQL API tests covering version/actor/clinic/algorithm/provenance/review/retirement and dependency drift/revocation matrices, concurrent retry/version/approval/revoke, no old fallback, audit rollback/read failure, SQL guards. Fresh/additive legacy preservation proof and official API/client/consumer compatibility. This slice does not activate offerings, payments, couples assessment or individualized care.
