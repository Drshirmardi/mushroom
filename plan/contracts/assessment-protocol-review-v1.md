Phase12/F12-PJ-O02; ADR-0022, owner-authorized backend implementation and physician-only approval boundary. Existing questionnaire authoring/engine/result/offer draft contracts unchanged. No business price or refund defaults.

## Authority and scope

Reuse G01 authority: current database DOCTOR role, linked active published profile, explicit same-active-clinic membership, current clinical-sign grant and owned active session. Ordinary ADMIN cannot approve or withdraw. ADMIN content manager with explicit scope may preview/read review history; qualified physicians also have a bounded nonpatient questionnaire queue. No role/grant expansion, patient data or generic clinical-record access. Educational protocol review does not establish scientific validity, diagnosis, personalized therapeutic diet or treatment approval.

The existing immutable PUBLISHED/RETIRED AssessmentVersion is the questionnaire source; no duplicate draft editor/engine. Exact supported WEIGHTED_SUM/v1 identity, canonical structure/content hash and owner-controlled same-clinic/same-locale ConsentPolicyVersion with purpose ASSESSMENT_PROCESSING form the protocol hash(schemaVersion1, assessmentVersionId, questionnaireContentHash, algorithmId/version, consentPolicyVersionId/contentHash, educationalOnly:true). Actual legal text must be explicitly supplied through existing release-managed consent CLI with the exact purpose/hash/environment/release reference. Default MEDICAL_INTAKE_PROCESSING and COUPLES_ACCOUNT_LINKING remain unchanged; no policy is automatically promoted/seeded. Patient medical intake/account-link consent does not imply assessment-processing consent.

## Append-only review ledger

One AssessmentProtocolReview table records monotonically numbered APPROVED or WITHDRAWN decisions per questionnaire. Every row retains source/consent/hash/algorithm/reviewer profile/user/session/time and idempotency fingerprint. No UPDATE/DELETE; no competing mutable approval state machine. Approval requires a structurally supported currently PUBLISHED questionnaire, exact recomputed canonical hash and ACTIVE purpose-matching consent. Physician explicitly attests reviewedQuestionnaireAndScoring:true, educationalOnly:true and noDiagnosisOrTherapeuticDiet:true against protocolHash. Software validates structure/provenance; the physician is responsible for professional evaluation.

Withdrawal names the current approval ID and expected reviewNumber, copies exact protocol facts, requires a bounded nonempty reason, and appends a final withdrawal of that approval. It remains possible when questionnaire/policy has retired. One withdrawal per approval. Only an explicit later numbered physician review can approve again; prior evidence is never rewritten/revived. A changed protocol/policy/reviewer authority cannot inherit approval. Latest decision plus present source/policy/physician authority determines usable clinical approval; a withdrawn latest approval never falls back. This usable approval is not commercial publication or patient consent.

## API

- GET /v1/clinical/assessment-protocols?page&pageSize&assessmentKey: qualified physician, bounded source queue(PUBLISHED/RETIRED only), metadata/latest recorded decision; no patient records. Page1..10000,size1..50,key1..100.
- GET /v1/clinical/assessment-protocols/:assessmentVersionId?consentPolicyVersionId and equivalent ADMIN /v1/admin/assessment-protocols/:assessmentVersionId: exact source/structure, technical algorithm, optional chosen/active assessment-processing consent, nullable computed protocolHash, current reviewNumber/latest review and approvalUsable/blockers. Missing policy is explicit empty readiness, not invented text. Chosen historical policy can be inspected, but only active matching policy approved. Retired source is readable, not newly approvable.
- GET either prefix /:assessmentVersionId/reviews?page&pageSize: retained paged history and no private actor/session identifiers.
- POST /v1/clinical/assessment-protocols/:assessmentVersionId/reviews, Idempotency-Key8..200 safe ASCII. Body: consentPolicyVersionId, protocolHash, expectedReviewNumber, reviewedQuestionnaireAndScoring:true, educationalOnly:true, noDiagnosisOrTherapeuticDiet:true. Server assigns next number; no arbitrary algorithm/weights/status/reviewer fields.

Only current APPROVED review; stale source/revision/hash409. Identical command replay returns original event even if subsequently withdrawn; response describes retained event, not current usability.
