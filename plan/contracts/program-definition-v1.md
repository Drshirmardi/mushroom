# Program clinical definition v1 — FROZEN

Phase12/F12-PJ-PG01, ADR-0030; continuous owner implementation authorization includes ready programs and custom physician programs. Depends on accepted G01/G02 and existing published directory/TreatmentPlan/clinical workflow. This first foundation does not activate a sale, payment entitlement, patient treatment or a second clinical record system.

One retained ProgramDefinitionVersion is justified by independently versioned program identity, exact authored curriculum/service specification, clinical approval and subsequent commercial purchase provenance. Immutable clinic/programKey/locale/version/kind/title/summary/category/body/safety/eligibility metadata, exact approved G01 references, optional published DoctorService clinical snapshot, canonical contentHash, independent create command/session and qualified approval/final revocation evidence. Reuse G01 professional authority, safety DTO, approved content verification and existing metadata audit. No actual clinical source, program text or legal policy is seeded.

Kinds: READY_EDUCATION is general educational curriculum, never an individualized therapeutic diet, diagnosis, medication or automatic TreatmentPlan. Require one to50 distinct exact approved same-clinic/locale G01 references; curriculum body is separately approved and is not exposed through G01 patient reads. Existing separately published educational sources retain their own access contract. CUSTOM_PROFESSIONAL_PLAN is a reviewed service specification, pins a real published same-clinic DoctorService and clinical snapshot (id/doctorId/serviceId/visitMode/durationMinutes), requires assigned professional review and eventual reuse of existing TreatmentPlan/publication/progress; it stores no patient plan or medical data. Optional supporting G01 references0..50. Prices, access duration, actual delivery/financial/refund/legal policy and patient eligibility remain separate commercial publication/access contracts. Assessment no-refund/minimum-age decisions are not silently applied to programs.

Program key uppercase stable within clinic/locale; versions consecutive under advisory serialization, kind cannot change under the same identity. No update/delete API; changes create a version. Same patient-free admin create command is idempotent for canonical normalized payload, changed reuse409. Content hashes cover the exact definition and bound clinical references, exclude future commercial price. Program definition cannot be created from foreign/missing/unapproved/noncurrent source/service. Current clinical source/service/approver loss makes dependencies/usable false without old-version fallback. A later price change alone does not invalidate clinical definition. No current availability is persisted.

ADMIN plus CONTENT_MANAGE/current actual admin role/live owned session/active-clinic membership may create/list/get and revoke a draft only. DOCTOR plus current SIGN/live linked active published same-clinic professional authority/current session/membership may list/get/approve and finally revoke. Ordinary ADMIN cannot approve or revoke an approved definition. Exact approval input: contentHash, reviewedProgramAndSafety:true, noAutomaticTherapyActivation:true. Same approved hash retry is a no-op; revocation is final, retained, and remains possible after dependencies retire. Current context rechecked and locked in the same transaction as mutation/audit. Reads have coherent snapshots and metadata-only audit, private/no-store; no patient endpoints in this foundation.

APIs: POST admin/program-definitions/versions (Idempotency-Key8..200); GET admin/program-definitions; GET admin/program-definitions/:id; POST admin/program-definitions/:id/revoke. GET clinical/program-definitions; GET clinical/program-definitions/:id; POST clinical/program-definitions/:id/approve; POST clinical/program-definitions/:id/revoke. Bounded page1+/pageSize1..50, optional programKey/status; strict DTOs reject patient/price/clinical bypass fields. Response exposes only privileged definition and approval timestamps/current dependency readiness, commercialReady:false. No beneficiary identifiers, price/checkout, implied medical clearance or automatic prescription. New stable errors PROGRAM_DEFINITION_NOT_FOUND/CONFLICT/INVALID.

Database validates immutable shape/FKs/actor-session/clinic/role approval, consecutive versions, exact supported reference/service snapshot and retained lifecycle. All checks reject NULL/unknown shape; current dependency predicate is server-authoritative, with explicit queryable usable status. App locks command→version→source/service consistently; approval locks professional authority→definition→dependencies. No irreversible side effect or external provider call.

Acceptance: actual independently authenticated admin creates both kinds from existing approved educational/published service sources; qualified physician exact review/approval/final revocation; ordinary admin/patient/foreign clinic/noncurrent profile/session/role/SIGN denial; strict malformed/safety/source/snapshot checks, no patient/private data, no purchase/therapy activation. Concurrent same/different commands and consecutive versions, immutable direct SQL/retained records/final approval, audit rollback, dependency retirement/reviewer loss/no fallback and price-only change compatibility. Fresh/additive populated migration preservation/no drift, focused existing G01/G02/directory/clinical compatibility, official additive API/client/consumer types/main review/evidence/isolated commit. Separate next batches must freeze commercial publication/entitlement and assigned custom delivery before claiming program purchase/delivery complete.
