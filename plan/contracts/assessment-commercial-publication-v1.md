## Commercial configuration and policy

Dashboard ADMIN+ASSESSMENTS_MANAGE with explicit active clinic membership and owned live session creates a new immutable O01 draft for each price change, then previews/publishes that exact version. Both INDIVIDUAL/COUPLES tariffs are configurable, positive integer IRR within existing money bounds; never hardcoded or overwritten. Publication requires PAID/PRE_START, minimumAgeYears18, existing WEIGHTED_SUM/v1, matching exact currently usable physician protocol and its assessment-processing consent, explicit retentionPolicyRef/resultVisibilityPolicyRef, no invitationTtlHours/entitlementValidityDays and no conflicting refundPolicyRef (absent or NO_REFUNDS). Technical fixed policy schemaVersion1: minimumAgeYears18, paymentPoint PRE_START, ordinaryRefunds false, patientCancellation false, invitationAutomaticExpiry false, entitlementAutomaticExpiry false. Expiring bank quotes remain separate. Results/attempts are retained under owner-supplied lawful policy; these flags do not authorize unlimited healthcare-data retention.

Owner-controlled ACTIVE same-clinic/same-locale ConsentPolicyVersion purpose ASSESSMENT_PURCHASE_TERMS supplies actual purchase/refund/retention/visibility text. Explicit CLI opt-in purpose; never seed fabricated text. Administrator attests reviewedTermsAndRetention:true against exact publicationHash. The software verifies exact source/hash/authority and attestation, not legal correctness. Ordinary ADMIN cannot medically approve; publication references O02 physician evidence. Linked-account consent does not authorize processing or joint-result sharing.

## Retained publication lifecycle

One AssessmentOfferingPublication record pins immutable offering draft, exact protocol approval, terms version/hash, fixed policy snapshot and publicationHash, publisher/session/time/key/fingerprint. Consecutive publicationNumber per clinic/offeringKey. One ACTIVE publication per key; publishing a replacement atomically retires the previous ACTIVE record with REPLACED actor/session/time, then inserts next record. Explicit ADMIN withdrawal retires current publication with WITHDRAWN; no restore/delete/content rewrite. Same exact command key/payload returns original historical publication after replacement/retirement, never reactivates it. Different payload409. New explicit publication required to reoffer an old tariff. Future purchases pin publication and amount; later price changes/retirement never alter receipts or ordinary paid entitlements.

Current commercial usability requires ACTIVE publication, still-DRAFT exact O01 source, supported configuration, exact currently usable protocol, exact active terms/hash and matching publicationHash. Source/policy/physician withdrawal blocks new purchase preparation; no fallback to older retired publication. This is a composable prerequisite inside the caller's transaction, not patient eligibility, clinical validity or financial entitlement. Couples additionally require separately approved participation/joint-result rules before checkout. This task has no patient catalog/checkout/entitlement routes and cannot charge anyone.
