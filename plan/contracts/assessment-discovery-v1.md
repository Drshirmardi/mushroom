# Assessment discovery/provenance v1 — additive extension

Frozen 2026-10-16 for F12-PJ-R02, dependent on R01/J01. Existing assessment-booking-v1 and reliability contracts remain immutable. This preserves existing get/save/submit behavior for owned IN_PROGRESS attempts, including a version retired after start. It adds the missing exact questionnaire retrieval; retirement still prevents starting a new attempt. No latest-version substitution, scoring/booking policy change or clinical approval is introduced. The J01 conservative resume-unavailable projection becomes resumeAvailable=true for a valid owned published-or-retired IN_PROGRESS attempt now that its questionnaire is retrievable. DRAFT versions and invalidated attempts are never resumable.

New PATIENT + ASSESSMENTS_READ_SELF, private/no-store endpoints:
- GET /v1/patients/me/assessment-submissions?page=1&pageSize=20&state=IN_PROGRESS|COMPLETE|INVALIDATED. Strict DTO, page max10000, pageSize1..50, deterministic startedAt/id descending, items/total/page/pageSize. Summaries have version identity/key/title/locale/versionNumber, state/revision/attempt/timestamps/resumeAvailable. No answers/score/result text. Counts and data share a repeatable-read transaction and mandatory minimized read audit.
- GET /v1/assessment-submissions/:id/questionnaire: owner+clinic scoped, noninvalidated source and version PUBLISHED/RETIRED, exact immutable version and content hash, structure identical to existing assessment-list schema. Completed historical questionnaire may be read; resumeAvailable only IN_PROGRESS. No other patient's answers or draft versions.
- GET /v1/assessment-submissions/:id/provenance: valid COMPLETE owner+clinic only. Questionnaire version/hash and persisted algorithmId/algorithmVersion/answer hash when present; missing historical metadata remains null/LEGACY_UNRECORDED. Never manufacture clinical approval or recalculate an old result. No answers/result text.

New completions persist technical algorithm identity WEIGHTED_SUM/v1, questionnaire hash and answer payload hash in the existing immutable resultSnapshot. This names the existing weighted-sum implementation only; no validation of temperament categories or clinical claims follows. Old immutable snapshots are unchanged. Algorithm behavior changes require a new identity/version. All existing result-returning endpoints retain their present access contract; paid/clinical-gated offerings must define one shared release check before activation, never rely on these legacy routes for paid access.

Every new sensitive read and its audit share a transaction and fail closed. Unknown/foreign/invalidated questionnaire/provenance targets return existing concealed404. No new table/migration or historical data rewrite. Acceptance: ownership/clinic/role/session gates, paging/filter bounds/stable ordering, exact retired version retrieval and existing saved-answer continuation, start refusal for retired version, no draft/invalidated leak, persisted-new versus unknown-old provenance, audit failures, existing reliability/journey regressions and official generated contracts.
