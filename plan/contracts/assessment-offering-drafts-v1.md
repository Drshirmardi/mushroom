# Assessment offering drafts v1

Frozen 2026-10-16 for F12-PJ-O01 / ADR-0019. Technical configuration only; new offerings cannot be published or sold in this slice. Existing assessment/payment contracts remain frozen and unchanged.

ADMIN + ASSESSMENTS_MANAGE + explicit ClinicalClinicAccess membership in the active clinic. Derive clinic server-side, no request clinic override. All routes /v1/admin/assessment-offerings; GET list (strict page1..10000/pageSize1..50, optional offeringKey/kind), GET :id, POST versions (required Idempotency-Key), POST :id/retire (idempotent target-state operation). Sensitive administrative reads/writes audit atomically and are private/no-store. Foreign resources concealed404; missing clinic membership403. New stable errors ASSESSMENT_OFFERING_NOT_FOUND, ASSESSMENT_OFFERING_INVALID, ASSESSMENT_OFFERING_CONFLICT; existing FORBIDDEN/IDEMPOTENCY_KEY_REQUIRED/IDEMPOTENCY_KEY_REUSED reused.

Create complete immutable draft version under offeringKey (uppercase stable identifier max80), kind INDIVIDUAL|COUPLES, title, exact same-clinic assessmentVersionId (PUBLISHED or RETIRED, not editable DRAFT), priceMode FREE|PAID, optional paymentPoint PRE_START|PRE_RESULT_UNLOCK, optional integer amountRial string and explicit currency IRR. FREE records zero and no payment point; PAID may remain price-incomplete in a draft, but if supplied amount must be positive within existing integer money bounds. Same key never changes kind, locale or questionnaire family. Algorithm id/version are nullable unapproved configuration references. Optional policy fields are strictly bounded draft values: minimumAgeYears, quoteTtlSeconds, entitlementValidityDays, invitationTtlHours, refundPolicyRef, consentPolicyVersionId, retentionPolicyRef, resultVisibilityPolicyRef. No submitted reference is treated as approval; optional consent reference must exist in the same clinic.

Version numbers are sequential per clinic/key under a database advisory lock. Same actor/idempotency key and canonical payload returns the original version even after retirement; changed payload conflicts, with no new version. Same-state retirement is safe. Content is append-only; status may only move DRAFT→RETIRED with a timestamp. Database rejects publication, content rewrites, deletion, version gaps, family/kind/locale changes and cross-clinic references. Creation records creator/key/hash for immutable replay evidence. Read DTO never returns the idempotency key/hash or actor identity. No medical answers, score or patient data are stored here.

Responses: id/key/version/kind/title/locale/status/questionnaire reference, price configuration, algorithm references, policy draft, createdAt/retiredAt, releaseReadiness { ready:false, blockers:string[] }. Mandatory gates include OWNER_POLICY_APPROVAL_REQUIRED, CLINICAL_RELEASE_APPROVAL_REQUIRED, DIGITAL_ACCESS_INTEGRATION_REQUIRED; conditional incomplete-price/policy/questionnaire/couples algorithm/session reasons are explicit. Draft infrastructure acceptance is not digital billing/couples/result completion. No patient-facing listing of drafts or runtime payment/eligibility mutation.

Acceptance: real PostgreSQL concurrent version/key replay, changed-payload conflict, database immutability/status/scope/family constraints, owner/membership/roles, strict input/query bounds, private read projection and audit rollback; all existing migrations replay fresh/upgrade without legacy data changes, official OpenAPI/client and focused current-domain regressions.
