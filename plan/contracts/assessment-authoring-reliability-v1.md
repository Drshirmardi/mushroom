# Assessment authoring reliability v1

Frozen 2026-10-16 for F12-PJ-R03; implements the existing assessment-booking-v1 canonical/scoring rules without changing that frozen document or scientific scoring semantics. Existing admin paths/DTO/status/error codes remain. No migration, approval of clinical content, payment or permissions change.

Draft create/update reject unknown question types, missing boolean weights, malformed/duplicate choice options, nonfinite scores/bounds, invalid or overlapping numeric ranges/result bands, invalid text limits, duplicate/canonical ids and malformed review/risk flags using existing422 ASSESSMENT_STRUCTURE_INVALID. Empty draft sections remain editable; publication requires at least one usable question. Duplicate of a historical version remains an editable copy with its original content hash; new publication validates the copied structure first. No old immutable/published result or questionnaire is rewritten. No fixed question count, temperament labels, clinical interpretation or weights are invented.

Create/duplicate allocate next version under a clinic/key/locale transaction advisory lock. Update/publish/archive lock the same-clinic source row before state validation and updates. A partial update merges with the latest locked draft, avoiding a concurrent title-only edit overwriting a structure-only edit. Same-field writes retain serialized last-write-wins compatibility; no stale-precondition guarantee is invented for old clients. Publication serializes its namespace and preserves one published version plus existing stable conflict codes. Already-published/already-retired operations retain idempotent no-write behavior.

Every changed create/update/duplicate/publish/archive and its existing audit share one transaction; audit failure rolls back all domain writes. No raw structure or medical values enter audit metadata. Existing ADMIN active-clinic contract remains; no new clinician qualification or multi-clinic authorization policy. Create/duplicate still create a new draft for each distinct legacy request (no new idempotency header/table); optional command-level replay is later work if adopted by consumers.

Acceptance: pre-fix PostgreSQL reproduction of invalid authoring/version race/audit partial persistence, then deterministic focused domain tests and actual PostgreSQL concurrency/rollback/lifecycle/clinic tests; existing admin and patient regression checks; source/test types and official contract freshness. Clinical release and commercial activation remain separate gates.
