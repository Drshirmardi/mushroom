# Mizaj authoring quick start (F12-PJ-M01)

Backend preparation only. Nothing in this guide publishes clinical content, charges for a draft or grants patient access. Existing physician-only review remains required; patient/runtime DIMENSION_RANK support is a separate integration task. The original CSV and source documents are unchanged.

1. Authenticate as an existing administrator with `assessments:manage`.
2. GET `/v1/admin/assessments/draft-presets/mizaj`. This returns the original owner-designated 11 questions and 44 options, candidate weights and 16 unreviewed educational display profiles. The CSV reference is deliberately not replaced by the 47-option DOCX version. Only questions 1/5/7/8/9 have proposed weights; other questions contribute no points pending clinical review. These are authoring choices, not an established diagnostic key.
3. POST the returned body to `/v1/admin/assessments` to create a new versioned DRAFT. Read it back with GET `/v1/admin/assessments/:id`.
4. Use synthetic answers with option IDs `o1`..`o4`, question IDs `q1`..`q11`. POST `/v1/admin/assessments/:id/scoring-preview` with `expectedContentHash` from the saved version, `syntheticAnswersOnly:true` and `answers`. Example: every answer `o1`, except `q8:o2` and `q9:o2`, yields totals DAMAVI=3/SAFRAVI=2 and the DAMAVI_SAFRAVI unreviewed profile. No answers or result are persisted.
5. Update candidate weights/profile text through the existing PATCH API and repeat with the new content hash. Both questions and result copy are bound to that hash. Old preview requests fail with `ASSESSMENT_PREVIEW_CONFLICT`. Duplicate creates a separate DRAFT version, preserving the original.

The four single profiles mean positive evidence for only one dimension. They do not invent a second identical label. Twelve other profiles represent ordered distinct positive first/second totals. A primary tie or tied runner-up selects no composite text. Explicit neutral options may be added with `scores:{}`; missing required responses are invalid and neutral/insufficient evidence never forces a result. `minInformativeAnswers` is configurable and validated against the number of contributing questions.

Profile copy consists of title, summary, reflective strengths prompts, attention prompts and a next step. It intentionally contains no disease prediction, therapeutic diet, moral judgment or compatibility verdict. All text is a plain-text, UNREVIEWED proposal. Clients must render it as escaped text. Display a preview label and do not present the administrator's synthetic preview as a saved patient result.

SchemaVersion2 is draft-only: publish returns 422. The existing dashboard visual editor understands only scalar scores; use the API to edit a dimension draft. PATCH cannot downgrade it to v1, and relabeling a DIMENSION_RANK definition as v1 is rejected. Current v1 questionnaire/payment/protocol/guidance/history paths are preserved. Before extending runtime delivery, separately freeze the versioned source algorithm/provenance/SQL/protocol/guidance/individual/couple payment and care boundaries and obtain qualified approval of the actual scoring rules and content. A dashboard editor/customer result screen is not included in M01.
